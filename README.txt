Этот архив содержит config.json с уже заполненными ID ПГО КАРАТЕЛИ.
Положите bot.py и config.json рядом. Существующие .env и базу не заменяйте.

ПГО КАРАТЕЛИ • Кадровый аудит
===========================

Отдельный Discord-бот на Python 3.11+. Не заменяет бота запроса ролей.

1. Распакуйте архив в новый проект Bothost, установите requirements.txt.
2. В архиве уже есть заполненный config.json. При развёртывании на другом сервере используйте config.example.json как образец. Заполните ID вашего сервера,
   двух текстовых каналов и отдельных ролей старшего состава (senior_role_id)
   и Начальника семьи (family_chief_role_id). Пример:
   "guild_id": "123456789012345678".
3. В ranks заполните ID званий по образцу. Порядок — от младшего к старшему.
   «Заместитель основателя» — последняя запись. Самого Основателя сюда не добавляйте.
   В departments укажите один ID или список ID ролей для каждого отдела.
   Пример: "Отдел логистики и снабжения": ["123456789012345678", "234567890123456789"].
   Старый формат с одним ID в кавычках тоже работает. Пустые места в списках
   замените реальными ID или удалите. Общие роли можно указать в нескольких
   отделах, но у каждого отдела должна быть хотя бы одна уникальная роль.
   Не используйте в departments ID ролей званий, должностей и увольнения.
   В dismissal_statuses оставьте только нужные статусы и укажите их ID.
   Если роль не используется, удалите её строку без лишней запятой.
   ID не должны повторяться между разными типами ролей. Роль проверяющих
   задаётся отдельно от званий.
4. В настройках хостинга укажите BOT_TOKEN или создайте .env по образцу.
   Токен в config.json не нужен.
5. Пригласите отдельное приложение бота со scopes bot и applications.commands.
   Боту нужны «Управлять ролями» и в двух каналах «Просматривать канал»,
   «Отправлять сообщения» и «Встраивать ссылки». Его высшая роль должна
   быть выше управляемых ролей и участников, которых он будет менять.
   Права администратора и привилегированные intents не нужны.
6. Запустите python -u bot.py. Выполните /setup_kadro с правом
   «Управление сервером». Команда публикует панель в настроенном канале.
   Для кнопок нужна роль старшего состава или Начальника семьи. Кадровик может менять
   только участников и роли ниже себя, кроме владельца сервера.
7. Проверяйте сначала на тестовом участнике.

Кадровик выбирает участника, новую роль и указывает причину.
Повышение и понижение меняют только звание. Перевод меняет весь набор
ролей отдела и сохраняет звание, должность и прочие роли.
Увольнение снимает только настроенные звания, отделы и прежние статусы.
Участника бот не удаляет с Discord-сервера и не снимает посторонние роли.

В кадровый журнал попадают только выполненные действия. Запись содержит
сотрудника, кадровика, снятые/выданные роли и причину. Журнал SQLite также
хранится в karateli_kadro.sqlite3. Сохраните базу на постоянном диске Bothost.
Настройки и токен старого бота не меняются.

Особое звание «Заместитель основателя» доступно для выдачи только роли
Начальника семьи. Бот также не даст старшему составу снять его понижением
или увольнением. Наличие «Администратора» не отменяет это правило внутри бота.
Если нужна такая же защита при ручной выдаче ролей, поставьте роль
«Заместитель основателя» выше всех ролей сотрудников с правом управления ролями,
которым её выдавать нельзя. Роль Начальника семьи должна быть выше неё,
а роль бота — выше всех ролей и участников, которыми он управляет.

Обновление существующего проекта: остановите бота, замените bot.py.
В текущем config.json сохраните ID сервера, каналов, статусов и старшего
состава. Добавьте family_chief_role_id, а ranks и departments обновите по
новому примеру. Не удаляйте .env и SQLite. Перезапустите бота и выполните
/setup_kadro, если нужно обновить текст панели.


Назначение на должность
---------------------
В config.json сохраните founder_role_id и добавьте ID должностей в extra_roles.
«Начальник отдела» — новая строка. Если такой роли нет, удалите строку.
В department_tags задаются сокращения отделов для ника, например ОЛС.
Если «Основатель» и «Начальник семьи» — одна роль, их ID совпадают.
ID «Заместитель основателя» берётся из ranks.

После обновления bot.py перезапустите бота и выполните /setup_kadro.
Старое сообщение с кнопками можно удалить вручную. Новая панель — меню.
Основатель или Заместитель основателя выбирает «Назначить на должность»,
участника, должность и отдел, затем проверяет имя и пишет причину.
Бот выдаёт роль должности, заменяет набор ролей отдела, сохраняет звание
и меняет ник, например «Начальник ОЛС | Иван Иванов».
Назначение на руководящую должность заменяет предыдущую настроенную
руководящую должность. «Сотрудник семьи» — дополнительная роль.
Для назначения нужно право бота «Управлять никнеймами». Роль бота должна
быть выше роли участника. Только успешные назначения попадают в аудит.
Ник при обычных повышениях, переводах и увольнениях не меняется.
Правило назначения самого Заместителя основателя не изменилось.

Личные уведомления
------------------
После каждого выполненного повышения, понижения, перевода, увольнения
или назначения бот отправляет участнику карточку в ЛС. В ней указаны
изменения, причина и отображаемое имя кадровика. Отказ Discord в отправке
ЛС не отменяет изменения и не мешает записи в аудит. Бот сообщает
кадровику, если ЛС не отправилось. Дополнительных настроек не требуется.


Общие роли подразделений
------------------------
Роли, встречающиеся у нескольких отделов (например, «Стажёр подразделения»
и «Сотрудник подразделения»), не определяют текущий отдел и не выдаются
обе автоматически. При переводе или назначении бот сохраняет те общие
роли, которые уже есть у участника, и заменяет только уникальные роли
отдела. При увольнении настроенные роли подразделений снимаются.
По умолчанию config.json ищется рядом с bot.py, независимо от папки
запуска. KADRO_CONFIG по-прежнему может указать другой файл.
